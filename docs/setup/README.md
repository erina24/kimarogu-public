# 環境構築と起動

この公開用コピーには、実際の認証情報・ユーザー登録データ・会議記録・Git履歴は含まれていません。
4人チームで制作したアプリのコードと、自分の検証環境で動かすための手順を収録しています。

- [Mac手順](mac.md)
- [Windows / PowerShell手順](windows.md)
- [アプリ概要・起動手順](../../README.md)

自分で管理するFirebaseプロジェクト、OpenRouterキー、ローカルDBを用意してください。
元チームの認証情報は使用しません。初回の所属登録スクリプトは4人分のUIDを要求します。
検証用アカウント4件を用意できない場合、現状のスクリプトのままでは初回登録を完了できません。

## AIエージェントと進める場合

ルートのREADMEと、自分のOSの手順書を読ませて、次の1操作ずつ確認してください。
`.env`、Firebase鍵、seed-users.json、Cookieの内容はAIやチャットへ渡しません。
既存のDB・起動中サービス・設定を確認し、初期登録やマイグレーションは自分の検証環境だけで実行します。
Git操作は起動に不要です。

## 確認状況

手順をコード・設定と静的に照合しています。公開用コピーでの全工程の実行、Windows実機での起動、外部AIとの接続確認は未実施です。
個人別の確認表は配布しません。確認結果はローカルの非公開メモに記録してください。

## 追加スクリプトとテスト

通常の議事録登録は画面から行います。`mastra` の `npm run ingest` は旧PDF取り込み用で、
別途用意した文字を選択できる架空サンプルPDFを `mastra/docs/` に置く必要があります。
このコピーにPDFは含めていません。旧PDF用インデックスを作り直すため、通常の起動手順では実行しません。

依存関係のインストール後、ルートから次のローカルテストを実行できます。

```sh
node --test tests/rag-retry.test.cjs
```

バックエンドのローカルテストは `backend` から実行します。

```sh
uv run python -B -m unittest discover -s ../tests -p 'test_minutes_retry.py'
```

これらは外部AIを呼びません。Mastraの検索・メモリ関連スクリプトは別途DB・設定が必要で、
実行内容により外部AIの利用や検証データの保存が発生します。
