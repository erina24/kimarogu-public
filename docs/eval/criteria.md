# AI の評価基準(ハーネス)

> 正解データの議事録は、すべて**架空**です(実在のチーム・人とは関係ありません)。置き場所:[samples/](samples/)

## 1. AI の出力チェック(AI の健康診断)
AI に決まった質問をして、答えを人の目で見て、下の条件どおりなら ○、ちがえば × を 非公開のローカル評価メモ に書きます。

| 見ること | 正しいと判断する条件【案】 | 確かめる質問・データ |
|---|---|---|
| 出力の型 | 毎回、決めた項目で返る([ai-design.md](../ai-design.md)) | 抽出の正解 S1〜S4 |
| 抽出の正しさ | 正解データとくらべて、決定事項の抜けがない・ないものを作らない | 抽出の正解 S1〜S4 |
| 根拠 | チャットの答えに出典(議事録名・日付)が必ずつく | Q1〜Q7・Q10〜Q14 |
| 最新の決定を優先 | 決定が変わったあと、新しいほうを答える | Q1(継続テスト) |
| わからないとき | 推測せず「見つかりませんでした」と言う | Q8 |
| データの分離 | ほかのチーム(もみじ)のデータが出てこない | Q8・Q9 |

## 3. 抽出の正解(機能①)
「担当なし」の表し方はまだ決まっていないので、いまは出力の型どおり `null` で書いています。

### S1(9/1 キックオフ)
```json
{
  "summary3": ["DB は PostgreSQL にする", "ログインはメールとパスワードにする"],
  "decisions": [
    { "content": "DB は PostgreSQL にする", "reason": "みんな Sec6 で使ったことがあるため", "replaces": null },
    { "content": "ログインはメールとパスワードにする", "reason": "すぐ作れるため", "replaces": null }
  ],
  "undecided": ["画面のデザイン"],
  "todos": [
    { "task": "ログイン画面を作る", "assignee": "はる", "due": "2026-09-05" },
    { "task": "DB の準備をする", "assignee": "なつ", "due": "2026-09-04" }
  ]
}
```
- 「おやつ記録アプリを作る」は、決定事項に入っても入らなくても OK(すでに決まっていた前提)

### S2(9/8 定例)
```json
{
  "summary3": ["ログインを Google ログインに変更する", "画面の色は青にする"],
  "decisions": [
    { "content": "ログインは Google ログインにする", "reason": "メンバー全員が Google アカウントを持っているため", "replaces": "ログインはメールとパスワードにする" },
    { "content": "画面の色は青にする", "reason": null, "replaces": null }
  ],
  "undecided": ["デプロイ先"],
  "todos": [
    { "task": "Google ログインに作りかえる", "assignee": "はる", "due": "2026-09-12" },
    { "task": "README を書く", "assignee": null, "due": null }
  ]
}
```
- 正しいと判断するポイント:`replaces` に前の決定が入る/README の担当・期限を**作らない**(null)

### S3(9/15 定例)
```json
{
  "summary3": ["決まったことはありません"],
  "decisions": [],
  "undecided": ["デプロイ先"],
  "todos": [
    { "task": "画面のテストをする", "assignee": "あき", "due": "2026-09-19" }
  ]
}
```
- 正しいと判断するポイント:決まったことを**作らない**/「半分くらいできた」は決定ではない

### S4(9/22 定例・長い議事録)
「必ず入る」決定がすべてあれば ○。「どちらでも OK」は入っても入らなくてもよい。

**決まったこと3行(例)**:画面の色をオレンジに変更する/デプロイ先は「おためしクラウド」にする/ログインの有効期限は5日にする(大事な順に3つなら、ほかの組み合わせでも OK)

| 決定事項(必ず入る) | 理由 | 前の決定(replaces) |
|---|---|---|
| ログインの有効期限は5日にする | 毎日ログインし直すのは面倒だから | null |
| 画面の色はオレンジにする | おやつの写真が明るく見えるから | **画面の色は青にする** |
| スマホでも見られるようにする | null | null |
| カロリーの欄は入れない | 入力が面倒で使われなさそうだから | null |
| 写真は1つのおやつに1枚まで | null | null |
| AI のおすすめ機能は WANT にする | null(「時間が足りるか心配」を理由にしても OK) | null |
| デプロイ先は「おためしクラウド」にする | 無料の枠があって、DB もいっしょに置けるから | null(前は「まだ決まっていない」だったので、前の決定ではない) |
| テストは「登録 → 一覧 → 消す」の3つを必ずやる | null | null |
| テストの結果はスプレッドシートに書く | null | null |
| バグを見つけたら Issue にする | null | null |

| 決定事項(どちらでも OK) |
|---|
| ログインは Google ログインのまま/フォントは今のまま/次の定例は 9/29 21:00/発表の練習は 10/6 |

| 未決事項(必ず入る) |
|---|
| メンバー以外が使えないようにする方法/アイコン/消したおやつを30日残すか/おすすめに使うモデル |

| ToDo | 担当 | 期限 |
|---|---|---|
| ログインの有効期限を5日にする | はる | 2026-09-25 |
| 画面の色をオレンジに変える | あき | 2026-09-26 |
| スマホの画面を直す | あき | null |
| デプロイの準備 | なつ | 2026-10-02 |
| 発表のスライドを作る | null | null |

- **× になるもの**:「なつはプリンが好き」「はるは木曜お休み」を決定や ToDo にする(雑談)/発表のスライドの担当・期限を作る/「バグをだれが直すか」を決めたことにする

|---|---|---|---|---|

## 5. 継続テストの進め方
「メモリ・本棚の状態が変わっても、答えの質が保たれるか」を見るため、**議事録を少しずつ増やしながら**同じ質問をします。記録は 非公開のローカル評価メモ。

| 回 | 本棚に入っている議事録 | とくに見ること |
|---|---|---|
| 1回目 | S1・M1 | Q1 は「メールとパスワード」が正解(まだ変更前)/Q8・Q9 でもみじが出ない |
| 2回目 | S1・S2 | Q1 が **Google ログイン** に変わるか(最新の決定を優先) |
| 3回目 | S1・S2・S3・S4 | Q3・Q4 が S4 の決定(オレンジ・おためしクラウド)に変わるか/長い議事録が入っても、ほかの答えがくずれないか/会話のメモリが増えてもずれないか/Q14(決定の変更前後のちがい) |

- 1回目の正解は、表の Q1・Q3・Q4・Q5・Q6・Q7・Q10 の一部が変わります(S2・S3 がまだないため)。テストの前に、評価者が「その回の正解」を 非公開のローカル評価メモ に書きます

公開用にはQ1〜Q14と、その根拠になる架空サンプルを収録しています。追加資料が必要な評価項目は含めていません。

### テストするときの条件
- 本棚に入れるチームID
  - S1〜S4(ひまわり)は、**テストする人(ログインした人)のチームID** で登録する(#49 で、チャットはログインした人のチームの本棚だけを探すようになったため)
  - M1(もみじ)は、**それとは別のチームID** で登録する
- Q8・Q9 は、**答えだけでなく出典にも、もみじの議事録が出ないこと**を確かめる
- Q3・Q4 は、**S4 を入れる前と後で正解が変わる**。下の表で、その回の正解を見ながら記録する

| 質問 | S4 を入れる前の正解 | S4 を入れたあとの正解 |
|---|---|---|
| Q3 画面の色は? | 青(S2) | **オレンジ**(以前は青・S4) |
| Q4 デプロイ先は決まった? | まだ決まっていない(S2・S3) | **おためしクラウド**(S4) |
