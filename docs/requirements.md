# 要件定義書(きまログ)

> 公開用の要件整理。4人チームで制作した共同成果です。
> 個人別の担当・合意記録・内部の進行記録は含めていません。

## 1. 前提・全体要件

### 1-1. 背景・目的
- チーム開発では「前回なにが決まった?」「なぜこの仕様?」がすぐにわからなくなり、議事録やチャットを探し直す
- AI に個人で質問すると、人によってわたす資料や前提がちがい、チームで確認する情報がそろわない
- **目的**:議事録から「決まったこと」を取り出して**チームの記録**として残し、メンバーの質問に**根拠(出典)つき**で答える AI アシスタントを作る

### 1-2. アプリ名
- **きまログ**(「決まった」+「ログ(記録)」。決まったことを、あとからたどれる)(10/27 決定)
- 候補だった「Kimeta」は、同じ名前の海外のアプリがあったため使わない

### 1-3. 使う人(ターゲット)
- チーム開発をしている小さなチーム(4〜5人)のメンバー。一般メンバーもログインして使う(10/20 決定)
- 会議に出られなかった人・決定の理由を忘れた人が、議事録を探し直さずに確認できる
- 開発チーム以外(お店のミーティング・PTA・サークルなど)でも使える形をめざす【今後】

### 1-5. 範囲(スコープ)
| 区分 | 中身 | 様子 |
|---|---|---|
| チームの MUST | ① 議事録 → 決まったこと3行・ToDo/② 根拠つき AI チャット/ログイン・権限/メモリ/AI の評価基準と継続テスト/決定事項の一覧(現在・以前) | ✅ |
| WANT(やった) | RAG 登録の再試行 | ✅ |
| 【今後】 | ホーム(決まったこと3行・自分の ToDo・担当者未定・理由・過去の議事録)/画面のタブ/議事録エクスポート/議事録の本文を見る画面/画面の入口のチェック/出典のしぼりこみ/保存のあとに直す・消す/ファイルからの取り込み/KPT ふりかえり/進捗・遅れの確認 | 未実装 |

## 2. 機能要件

### 2-1. 業務の流れ
```
ログイン → 議事録を貼る → AI(Workflow)が整理(決まったこと3行・決定事項・未決事項・ToDo)
→ 人が確認して直す → 保存(前の決定は「以前」に)→ AI 検索用の本棚にも登録
→ チャットで質問 → 自分のチームの議事録から探して、出典つきで答える
→ ダッシュボードで「最新の決定」「以前の決定」を見る
```

### 2-2. 機能一覧
| # | 機能 | 中身 | 様子 |
| --- | --- | --- | --- |
| F0 | ログイン確認の共通部品 | Next.js のサーバーで「だれ?どのチーム?」を FastAPI(`GET /api/auth/me`)に聞く。AI を呼ぶ前・保存の前に必ず通る。チームID・ユーザーID は画面から受け取らない | ✅ |
| F1 | ログイン・権限 | Firebase の Google ログイン → session Cookie。一般メンバーもログインできる。所属・役割は DB の users。メンバーでない人には「利用権限がありません」 | ✅ |
| F2 | 議事録の登録 | タイトル・会議の日時・本文を貼りつける(本文は10000文字まで) | ✅ |
| F3 | AI 抽出 | Workflow で、決まったこと3行(1〜3行)・決定事項(理由・前の決定)・未決事項・ToDo(担当・期限)を決めた形で返す | ✅ |
| F4 | 確認して保存 | 人が直してから保存。前の決定は「以前」(previous)にして履歴を残す。担当が見つからない ToDo は担当者未定。二重保存は 409 | ✅ |
| F5 | 決定事項の一覧 | 「最新の決定」(current)と「以前の決定」(previous)をダッシュボードで見る | ✅ |
| F6 | 根拠つきチャット | 自分のチームの議事録だけを探し、「関連する議事録」(議事録名・日付)つきで答える。続けて質問しても毎回検索する。見つからないときは推測せず「議事録の中に見つかりませんでした」 | ✅ |
| F7 | メモリ | 会話を PostgreSQL に残し、AI が見るのは直近20件。ユーザーID+チームID で分ける | ✅ |
| F8 | AI 検索への登録 | 保存のあと、チームID・議事録名・日付(日本時間)つきで本棚 `team_minutes` に登録。合言葉(RAG_INGEST_SECRET)つき。失敗したら「保存は成功・登録だけ失敗」と出し、再試行できる | ✅ |

- 議事録に書いていない決定は、非公開の連絡手段 などの文を議事録の画面に貼って登録する(10/21)
- 保存のあとに議事録を直す・消す機能はない【今後】(直したときの本棚の入れなおしも)

## 3. 非機能要件
| 項目 | 内容 | 様子 |
|---|---|---|
| セキュリティ | ほかのチームのデータは見えない。① DB:ログインの情報から取ったチームID で制限 ② AI 検索:自分のチームの本棚だけ ③ 会話メモリ:ユーザーID+チームID で分ける/RAG 登録は合言葉つき/出典は AI に作らせない | ✅ |
| 秘密の情報 | .env・API キー・Firebase の鍵・UID はコミットしない・貼らない。Firebase の鍵は各自がコンソールで発行 | ✅ |
| 個人情報 | 議事録やテストデータに個人情報を入れない(サンプルは架空) | ✅ |
| 使いやすさ | 画面は4つ。AI の結果は人が直してから保存/文字を見やすく | ✅ |
| 速さ | チャットは約10〜30秒/**抽出は約30〜52秒**(元の資料に記載の参考値。公開用コピーでは未計測)→ 待ち時間の短縮・ストリーミングは【今後】 | 🟡 |
| 対応環境 | Mac・Windows で起動できる(docs/setup/ の手順)/ブラウザで使う | 公開用コピーでは実行未確認 |
| 使う AI | 利用者が用意する OpenRouter:チャット・抽出 `gpt-5-nano`/埋め込み `text-embedding-3-small` | ✅ |

## 4. AI の評価・継続テスト
| 見ること | 合格の目安 |
|---|---|
| 出力の型 | 毎回、決めた項目で返る(Workflow の形のチェック) |
| 抽出の正しさ | 正解データとくらべて、決定事項の抜けがない・ないものを作らない |
| 根拠 | チャットの答えに出典が必ずつく(AI に書かせず検索結果から) |
| 最新の決定を優先 | 決定が変わったあと、新しいほうを答える |
| わからないとき | 推測せず「見つかりませんでした」と言う |
| データの分離 | ほかのチーム(もみじ)のデータが答えにも出典にも出てこない |

- 継続テスト:架空の議事録(S1〜S4・もみじ M1)を少しずつ本棚に増やしながら、同じ質問(Q1〜Q14)で回答の変化を確認する
- のこりの課題:抽出の抜け(理由・未決)・Q4・Q12 → 【今後】
- くわしくは [eval/criteria.md](eval/criteria.md)
